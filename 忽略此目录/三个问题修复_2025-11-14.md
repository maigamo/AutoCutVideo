## 问题一：保存剪辑预设失败 ✅

### 错误信息
```
Error: An object could not be cloned.
```

### 原因分析
IPC 通信时尝试传递包含复杂嵌套对象的 `settings.value`，其中 `paths` 对象包含了 `customDownloadDir` 等可能为 `undefined` 的属性，导致序列化失败。

### 解决方案
修改 `Settings.vue` 的 `saveSettings` 函数，只传递需要保存的设置部分，排除 `paths`（路径通过专门的 API 单独管理）。

**修改前**：
```typescript
const result = await window.api.invoke('settings:set', settings.value)
```

**修改后**：
```typescript
const settingsToSave = {
  general: settings.value.general,
  editing: settings.value.editing,
  logging: settings.value.logging
}

const result = await window.api.invoke('settings:set', settingsToSave)
```

**文件**：`src/renderer/src/views/Settings.vue`

## 问题二：修改剪辑后视频文件名格式 ✅

### 需求
剪辑后的视频文件名应该是：`原视频文件名_edit.mp4`

### 原实现
使用 UUID 生成随机文件名：
```typescript
const filename = `${uuidv4()}.mp4`
```

例如：`a1b2c3d4-e5f6-7890-abcd-ef1234567890.mp4`

### 新实现
使用原视频文件名 + `_edit` 后缀：
```typescript
const originalBasename = path.basename(filePath, path.extname(filePath))
const filename = `${originalBasename}_edit.mp4`
```

**示例**：
- 原视频：`TT_20251114_074152.mp4`
- 剪辑后：`TT_20251114_074152_edit.mp4`

**优势**：
- ✅ 文件名有意义，易于识别
- ✅ 保持与原视频的关联关系
- ✅ 便于批量管理和查找

**文件**：`src/main/ipc/download.ipc.ts`

## 问题三：视频管理页面加载失败 ✅

### 错误信息
```
Error: No handler registered for 'database:videos:list'
```

### 原因分析
前端 `VideoManagement.vue` 调用了 `database:videos:list` IPC 处理器，但后端只实现了 `db:query:videos`，两者名称不匹配。

### 解决方案
在 `database.ipc.ts` 中添加 `database:videos:list` 处理器。

**新增代码**：
```typescript
// 获取视频列表（前端使用）
ipcMain.handle('database:videos:list', async (event, filter: any = {}) => {
  try {
    const { is_edited, batch_id } = filter
    const db = require('../database/connection').getDatabase()
    
    let sql = 'SELECT * FROM videos WHERE 1=1'
    const params: any[] = []
    
    if (is_edited !== undefined) {
      sql += ' AND is_edited = ?'
      params.push(is_edited ? 1 : 0)
    }
    if (batch_id) {
      sql += ' AND batch_id = ?'
      params.push(batch_id)
    }
    
    sql += ' ORDER BY created_at DESC'
    
    const videos = db.prepare(sql).all(...params)
    
    return { success: true, data: videos }
  } catch (error: any) {
    logger.error('获取视频列表失败', { module: 'database', error })
    return { success: false, error: error.message }
  }
})
```

**功能**：
- ✅ 支持按 `is_edited` 过滤（原视频/剪辑后视频）
- ✅ 支持按 `batch_id` 过滤
- ✅ 按创建时间倒序排列
- ✅ 返回标准格式的响应

**文件**：`src/main/ipc/database.ipc.ts`

## 技术细节

### IPC 序列化规则

**可序列化的类型**：
- 基本类型：string, number, boolean, null
- 数组：Array
- 普通对象：Plain Object（不含函数、Symbol、undefined）

**不可序列化的类型**：
- 函数
- Symbol
- undefined（对象属性）
- 循环引用
- 类实例（非普通对象）

**最佳实践**：
```typescript
// ❌ 错误：直接传递响应式对象
window.api.invoke('settings:set', settings.value)

// ✅ 正确：传递简单对象
const settingsToSave = {
  general: settings.value.general,
  editing: settings.value.editing,
  logging: settings.value.logging
}
window.api.invoke('settings:set', settingsToSave)
```

### 文件名生成策略

**方案对比**：

| 方案 | 优点 | 缺点 | 适用场景 |
|------|------|------|----------|
| UUID | 唯一性强 | 无意义，难识别 | 临时文件 |
| 时间戳 | 有序，易排序 | 可能重复 | 单用户场景 |
| 原名_edit | 关联性强，易识别 | 可能重名 | 一对一剪辑 ✅ |
| 原名_时间戳 | 兼具优点 | 文件名较长 | 多次剪辑 |

**当前选择**：`原文件名_edit.mp4`

**原因**：
- ✅ 符合用户习惯
- ✅ 保持与原视频的关联
- ✅ 便于批量管理
- ✅ 文件名简洁明了

**潜在问题及解决**：
- 问题：同一原视频多次剪辑时文件名冲突
- 解决：当前场景下一个原视频只剪辑一次，如需支持多次剪辑，可改为 `原名_edit_时间戳.mp4`
