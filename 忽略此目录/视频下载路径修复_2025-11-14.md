# 视频下载路径修复方案

## 修复时间
2025-11-14 15:37

## 问题描述

### 用户问题
用户下载视频后，日志显示文件保存到了 AppData 目录：
```
C:\Users\Administrator\AppData\Roaming\autocutvideo-electron\videos\raw\TT_20251114_072926.mp4
```

但是在应用中找不到对应的视频文件。

### 根本原因

1. **配置缓存问题**：
   - electron-store 会将配置持久化到系统目录
   - 首次运行时使用的是旧的 AppData 默认路径
   - 即使代码中的 defaultConfig 改了，已存在的配置文件不会自动更新

2. **文件分散问题**：
   - 已下载的视频文件存储在 AppData 目录
   - 数据库记录的路径也是 AppData 路径
   - 应用前端可能从项目目录查找文件，导致找不到

## 技术方案选择

### 方案A：先设置下载路径（✅ 推荐，已实施）

**优点**：
- 代码简洁，无需额外文件操作
- 性能好，避免文件移动的 I/O 开销
- 可靠性高，减少文件操作失败风险
- Playwright 原生支持 `downloadsPath` 配置

**缺点**：
- 需要确保配置正确初始化
- 需要处理历史遗留文件

**实现方式**：
```typescript
// 1. 浏览器初始化时设置下载目录
this.browser = await chromium.launch({
  downloadsPath: configService.getActualPath('downloadDir')
})

// 2. 下载时直接保存到目标路径
const savePath = path.join(downloadDir, filename)
await download.saveAs(savePath)
```

### 方案B：下载后移动文件（❌ 不推荐）

**优点**：
- 可以在下载完成后验证文件
- 可以统一处理文件重命名

**缺点**：
- 代码复杂，需要处理文件移动逻辑
- 性能差，额外的文件 I/O 操作
- 可靠性低，移动过程可能失败
- 需要处理临时文件清理

## 实施的修复措施

### 1. 修复 ConfigService（✅ 已完成）

**文件**：`src/main/services/ConfigService.ts`

**修改内容**：
```typescript
class ConfigService {
  constructor() {
    this.store = new Store<AppConfig>({
      defaults: defaultConfig
    })
    this.defaultPaths = defaultConfig.paths
    
    // 修复旧的AppData路径问题
    this.fixLegacyPaths()  // ✅ 新增
    
    // 确保默认路径存在
    this.ensureDefaultDirectories()
    
    // 初始化日志配置
    this.initializeLogger()
  }
  
  /**
   * 修复旧的AppData路径问题
   * 如果路径中包含AppData，则强制更新为项目根目录
   */
  private fixLegacyPaths(): void {
    try {
      const paths = this.get('paths')
      let needUpdate = false
      
      const pathKeys: Array<'downloadDir' | 'outputDir' | 'musicDir' | 'tempDir'> = 
        ['downloadDir', 'outputDir', 'musicDir', 'tempDir']
      
      pathKeys.forEach(key => {
        const currentPath = paths[key]
        if (currentPath && currentPath.includes('AppData')) {
          paths[key] = this.defaultPaths[key]
          needUpdate = true
          console.log(`已修复路径 ${key}: ${currentPath} -> ${this.defaultPaths[key]}`)
        }
      })
      
      if (needUpdate) {
        this.set('paths', paths)
        console.log('路径配置已更新为项目根目录')
      }
    } catch (error) {
      console.error('修复路径配置失败:', error)
    }
  }
}
```

**效果**：
- ✅ 应用启动时自动检测并修复 AppData 路径
- ✅ 强制使用项目根目录路径
- ✅ 更新持久化配置文件

## 技术细节

### 下载流程

```
用户输入URL
    ↓
download.ipc.ts: 创建下载任务
    ↓
生成保存路径 (使用 configService.getActualPath)
    ↓
DownloadWorker.ts: 执行下载
    ↓
Playwright: 访问第三方下载站点
    ↓
获取实际下载链接
    ↓
download.saveAs(savePath) - 直接保存到项目目录
    ↓
更新数据库记录
    ↓
通知前端完成
```

### 关键代码路径

1. **路径获取**：
```typescript
// src/main/ipc/download.ipc.ts:110
const downloadDir = configService.getActualPath('downloadDir')
const filename = `${uuidv4()}.mp4`
const savePath = path.join(downloadDir, filename)
```

2. **浏览器配置**：
```typescript
// src/main/workers/DownloadWorker.ts:23
this.browser = await chromium.launch({
  headless: false,
  downloadsPath: configService.getActualPath('downloadDir'),
  // ...
})
```

3. **文件保存**：
```typescript
// src/main/workers/DownloadWorker.ts:272
await download.saveAs(savePath)
```

4. **文件名生成**：
```typescript
// src/main/workers/DownloadWorker.ts:171-173
const platform = task.url.includes('tiktok.com') ? 'TT' : 'DY'
const timestamp = new Date().toISOString().replace(/[-:]/g, '').replace('T', '_').split('.')[0]
const filename = `${platform}_${timestamp}.mp4`
```

格式示例：`TT_20251114_072926.mp4`
- TT: TikTok 平台
- 20251114: 2025年11月14日
- 072926: 07:29:26
