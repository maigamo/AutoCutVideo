## 🔍 问题一：Settings.vue 保存设置失败

### 错误信息
```
Error: An object could not be cloned.
    at saveSettings (Settings.vue:401)
```

### 根本原因分析

**表面原因**：
- IPC 通信时无法序列化传递的对象

**深层原因**：
1. **应用使用旧的编译代码**
   - 之前已经修复过此问题（排除 `paths` 对象）
   - 但应用仍在使用 `dist-electron/` 中的旧编译代码
   - 热更新只更新了渲染进程，主进程需要重新构建

2. **IPC 序列化限制**
   - Electron IPC 使用结构化克隆算法（Structured Clone Algorithm）
   - 不支持序列化：函数、Symbol、undefined（作为对象属性）、循环引用
   - Vue 响应式对象包含内部属性（如 `__v_isRef`）可能导致序列化失败

### 解决方案

**已修复代码** (`Settings.vue`):
```typescript
// 保存设置
const saveSettings = async () => {
  try {
    // 准备要保存的设置，排除 paths（路径单独管理）
    const settingsToSave = {
      general: settings.value.general,
      editing: settings.value.editing,
      logging: settings.value.logging
    }
    
    const result = await window.api.invoke('settings:set', settingsToSave)
    if (result.success) {
      ElMessage.success('设置已保存')
    } else {
      ElMessage.error(result.error || '保存失败')
    }
  } catch (error) {
    console.error('保存设置失败:', error)
    ElMessage.error('保存设置失败')
  }
}
```

**修复策略**：
1. ✅ 只传递简单的 POJO (Plain Old JavaScript Object)
2. ✅ 排除 `paths` 对象（通过专门的 API 管理）
3. ✅ 避免传递 Vue 响应式对象的内部属性

## 🔍 问题二：视频列表加载失败

### 错误信息
```
MODULE_NOT_FOUND
requireStack: ["C:\\open_workspace\\AutoCutVideo-dev\\dist-electron\\main\\index.js"]
```

### 根本原因分析

**问题代码**：
```typescript
const db = require('../database/connection').getDatabase()
```

**原因链**：

1. **动态 require 路径解析失败**
   ```
   TypeScript 源码: src/main/ipc/database.ipc.ts
   require('../database/connection')
       ↓ TypeScript 编译
   编译后代码: dist-electron/main/index.js (单文件打包)
   require('../database/connection')  ❌ 路径不存在
   ```

2. **打包工具处理差异**
   - Vite/Rollup 打包主进程时，可能会将所有模块打包成单文件
   - 动态 `require()` 不会被正确处理
   - 相对路径在打包后失效

3. **设计问题**
   - 应该使用静态导入，而不是动态 require
   - 已有 `DatabaseService` 和 `getDatabase` 封装，应该使用它们

### 解决方案

#### 方案一：使用 dbService（推荐） ✅

**适用场景**：DatabaseService 已提供的方法

```typescript
// ❌ 错误方式
const db = require('../database/connection').getDatabase()
const videos = db.prepare('SELECT * FROM videos').all()

// ✅ 正确方式
```

**优势**：
- ✅ 代码简洁，语义清晰
- ✅ 类型安全
- ✅ 统一的数据访问层
- ✅ 避免打包问题

#### 方案二：使用静态导入 ✅

**适用场景**：需要自定义 SQL 查询

```typescript
// ❌ 错误方式
const db = require('../database/connection').getDatabase()

// ✅ 正确方式
import { getDatabase } from '../database/connection'
const db = getDatabase()
```

**修复示例**：

**修复前**：
```typescript
ipcMain.handle('db:query:tasks', async (event, filter: any = {}) => {
  const db = require('../database/connection').getDatabase()  // ❌
  const tasks = db.prepare('SELECT * FROM tasks WHERE 1=1').all()
  return { success: true, data: tasks }
})
```

**修复后**：
```typescript
import { getDatabase } from '../database/connection'  // ✅ 顶部导入

ipcMain.handle('db:query:tasks', async (event, filter: any = {}) => {
  const db = getDatabase()  // ✅
  const tasks = db.prepare('SELECT * FROM tasks WHERE 1=1').all()
  return { success: true, data: tasks }
})
```

#### 方案三：使用 dbService 封装 ✅

**最佳实践**：

```typescript
ipcMain.handle('database:videos:list', async (event, filter: any = {}) => {
  try {
    const { is_edited, batch_id } = filter
    
    // 使用 dbService 替代直接数据库操作
    let videos: any[]
    
    if (is_edited !== undefined) {
      videos = dbService.getVideosByType(is_edited)
    } else {
      videos = dbService.getAllVideos()
    }
    
    // 如果有 batch_id 过滤，进一步筛选
    if (batch_id) {
      videos = videos.filter(v => v.batch_id === batch_id)
    }
    
    return { success: true, data: videos }
  } catch (error: any) {
    logger.error('获取视频列表失败', { module: 'database', error })
    return { success: false, error: error.message }
  }
})
```

## 🔧 技术深度分析

### 1. Electron IPC 序列化机制

#### 支持的数据类型

```typescript
// ✅ 可序列化
const goodData = {
  string: 'hello',
  number: 42,
  boolean: true,
  null: null,
  array: [1, 2, 3],
  object: { nested: { deep: 'value' } },
  date: new Date(),
  regexp: /pattern/g,
  map: new Map([['key', 'value']]),
  set: new Set([1, 2, 3])
}

// ❌ 不可序列化
const badData = {
  function: () => {},
  symbol: Symbol('test'),
  undefined: undefined,  // 作为对象属性
  circular: null  // 循环引用
}
badData.circular = badData
```

#### 最佳实践

```typescript
// ❌ 直接传递响应式对象
await window.api.invoke('save', reactiveData.value)

// ✅ 提取纯数据
await window.api.invoke('save', JSON.parse(JSON.stringify(data)))

// ✅ 手动构造对象
await window.api.invoke('save', {
  field1: data.field1,
  field2: data.field2
})
```

### 2. TypeScript 模块导入机制

#### require vs import

```typescript
// require - 运行时动态加载
const module = require('./module')  // ❌ 打包后路径可能失效

// import - 编译时静态分析
import { func } from './module'  // ✅ 打包工具可以正确处理
```

#### 打包影响

```
开发环境 (源码运行):
  src/main/ipc/database.ipc.ts
  require('../database/connection')  ✅ 相对路径正确

生产环境 (打包后):
  dist-electron/main/index.js (所有模块打包成单文件)
  require('../database/connection')  ❌ 路径不存在
```

### 3. 数据访问层设计模式

#### 三层架构

```
前端 (Renderer Process)
    ↓ IPC
IPC 处理器 (Main Process)
    ↓ 业务逻辑
DatabaseService (数据访问层)
    ↓ SQL
SQLite 数据库
```

#### 职责划分

```typescript
// ❌ 不好的设计：IPC 直接操作数据库
ipcMain.handle('get-users', () => {
  const db = getDatabase()
  return db.prepare('SELECT * FROM users').all()
})

// ✅ 好的设计：通过服务层
class UserService {
  getAllUsers() {
    const db = getDatabase()
    return db.prepare('SELECT * FROM users').all()
  }
}

ipcMain.handle('get-users', () => {
  return userService.getAllUsers()
})
```

## 🐛 同类问题预防

### 1. 代码规范

**规则一：禁止使用动态 require**

```typescript
// ❌ 禁止
const module = require('./path/to/module')

// ✅ 推荐
import { something } from './path/to/module'
```

**规则二：使用服务层封装数据库操作**

```typescript
// ❌ 禁止在 IPC 处理器中直接写 SQL
ipcMain.handle('api', () => {
  const db = getDatabase()
  return db.prepare('SELECT ...').all()
})

// ✅ 推荐通过 Service
ipcMain.handle('api', () => {
  return dbService.getSomething()
})
```

**规则三：IPC 传递简单对象**

```typescript
// ❌ 禁止传递响应式对象
window.api.invoke('save', vueRef.value)

// ✅ 推荐构造纯对象
window.api.invoke('save', {
  field1: data.field1,
  field2: data.field2
})
```
